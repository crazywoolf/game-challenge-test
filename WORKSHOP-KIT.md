# Памятка ведущему: собираем Game Challenge

Готовые тексты для Zoom-встречи с ребятами 11–13 лет: анкета, генерация персонажей и общей картинки команды, создание раннера и публикация через GitHub Pages.

## 1. Что попросить написать в чате

Предложите придумать героя, а не присылать личные данные. Настоящие имя и фамилия, школа, контакты и фотографии не нужны. Игровые правила заранее не объясняйте: попросите рассказать о повседневных ощущениях, а затем вместе превратите ответы в элементы игры. Можно пропустить любой пункт. Для учёта ответов ведущий присваивает сообщению номер `001`, `002` и т. д.

**Сообщение участникам (можно скопировать в чат):**

> Придумай своего героя для нашей игры. Напиши одним сообщением:
>
> **Внешность:** девочка / мальчик / нейтральный образ; цвет и причёска волос; цвет глаз; цвет кофты; цвет штанов; цвет кроссовок.
>
> А теперь три вопроса про обычный день:
> - Что тебя утомляет или уже надоело?
> - Что тебя радует?
> - А что радует оооочень сильно — прям «ура!»?
>
> Можно отвечать коротко, пропускать вопросы и писать про любую мелочь. Не нужно объяснять личные ситуации или упоминать конкретных людей. Не указывай настоящее имя, фамилию, школу и другие личные данные.
>
> **Пример:** Внешность: нейтральный образ, короткие зелёные волосы, карие глаза, жёлтая кофта, синие штаны, красные кроссовки. Утомляет: долго ждать. Радует: прогулка с музыкой. Оооочень радует: когда получается то, что долго тренировался делать.

**Поля для записи ответов:**

| Поле | Что записать |
| --- | --- |
| `response_id` | Порядковый номер ответа, без имени участника |
| `gender_presentation` | Девочка, мальчик или нейтральный образ — только по ответу |
| `hair_color`, `hairstyle` | Цвет и причёска волос |
| `eye_color` | Цвет глаз |
| `shirt_color` | Цвет кофты |
| `pants_color` | Цвет штанов |
| `sneaker_color` | Цвет кроссовок |
| `tired_of` | Дословный короткий пересказ ответа «что утомляет или надоело» |
| `joy` | Дословный короткий пересказ ответа «что радует» |
| `big_joy` | Дословный короткий пересказ ответа «что радует оооочень сильно» |

Не додумывайте внешность за участника. Если поле пропущено, используйте нейтральный яркий вариант, одинаково допустимый для любого героя. Ответы про чувства храните отдельно от игровых категорий, а при подготовке игры преобразуйте их в понятные предметы: `tired_of` — в лёгкие игровые препятствия (`jump_over` или `duck_under`, в зависимости от подходящего образа), `joy` — в собираемые бонусы энергии (`energy_pickup`), `big_joy` — в редкий бонус временного роста (`temporary_growth_pickup`). Если мысль абстрактная, подберите добрую визуальную метафору и не меняйте её смысл. Не превращайте в препятствие конкретных людей, конфликты или личные истории; такие детали обобщите или не используйте. Затем сведите голоса отдельно по игровым категориям и возьмите самые популярные 2–3 идеи; при равенстве оставьте обе. Участники отвечают про себя и не обязаны придумывать игровые предметы.

## 2. Промпт для генерации персонажа по ответу

Подставьте поля одного ответа. Повторяйте запрос отдельно для каждого `response_id`, чтобы получить отдельный файл на каждого героя. Используйте только вымышленные описания из чата, не ищите и не добавляйте реальные фотографии участников.

```text
Создай одного вымышленного игрового персонажа для цветного браузерного раннера по ответу ниже.

ID ответа: [response_id]
Образ: [gender_presentation]
Волосы: [hair_color], [hairstyle]
Глаза: [eye_color]
Кофта: [shirt_color]
Штаны: [pants_color]
Кроссовки: [sneaker_color]

Изобрази дружелюбного мультяшного ребёнка примерно возраста игроков, строго в профиль, бегущего вправо. Персонаж должен целиком помещаться в квадратный холст: не обрезай голову, руки, ноги или обувь. Один кадр бега, одна фигура.

Стиль: чёткая контрастная цветная пиксельная графика классического браузерного раннера; простые крупные ступенчатые формы, насыщенные цвета. Цвет волос, видимый глаз, кофты, штанов и кроссовок должны различаться и оставаться читаемыми при уменьшении до 50 × 50 пикселей. Держи одинаковые ракурс, пропорции и масштаб для всей серии персонажей.

Формат: PNG, 512 × 512 пикселей, прозрачный фон. Не добавляй землю, тень, фон, предметы, препятствия, других героев, надписи, буквы, цифры, рамку или логотип. Не добавляй внешние признаки, которых нет в ответе; если поле пустое, выбери простой нейтральный вариант.

Это вымышленная игровая иллюстрация, не портрет и не точное сходство с реальным ребёнком. Имя итогового файла: avatar-[response_id].png.
```

В текущем проекте картинки кладутся в `images/characters/`, например `images/characters/avatar-001.png`. Проверьте после генерации, что фон действительно прозрачный, целый персонаж виден, а файл соответствует своему ID.

## 3. Промпт для общего изображения команды

Передайте генератору созданные аватары как референсы и вставьте этот текст:

```text
Создай одну общую весёлую командную иллюстрацию, используя приложенные игровые аватары как точные референсы персонажей. Сохрани для каждого героя его цвет волос, причёску, глаза, кофту, штаны и кроссовки. Не добавляй новых участников и не убирай приложенных.

Покажи всю команду вместе в одном пространстве, как дружеское групповое фото после забега. Персонажи стоят на общей поверхности: подошвы касаются одной и той же линии земли, рост и перспектива согласованы, расстояния между людьми правдоподобные. Камера на уровне глаз, единое освещение и единый масштаб. Герои могут слегка повернуться друг к другу и естественно взаимодействовать, но лица и одежда каждого остаются видны; никто не заслоняет другого целиком. Не размещай персонажей отдельными несвязанными наклейками и не заставляй их парить.

Композиция: горизонтальный кадр, вся команда целиком помещается, вокруг немного свободного места. Если героев много, расположи их в два неглубоких ряда с естественной перспективой, сохранив одинаковый видимый масштаб. Яркая дружелюбная цветная пиксельная стилистика как у игры. Простая общая площадка и лёгкий праздничный фон допустимы.

Не добавляй текст, подписи, номера, логотипы, рамки, лишних людей или реальные фотографии. Не меняй одежду и отличительные цвета аватаров.
```

Если нужно получить лица и одежду максимально похожими на игровые спрайты, приложите все аватары к одному запросу. Для очень большой команды лучше сделать несколько изображений, чтобы генератор не потерял отдельных героев.

## 4. Промпт для создания игры

Используйте его в кодовом помощнике, когда собраны анкеты, сводка голосов и изображения. Вставьте под ним сводку голосования и список файлов.

```text
Помоги вместе со мной сделать цветную браузерную игру-раннер для встречи с ребятами 11–13 лет. Работаем в папке проекта. Сначала осмотри файлы и коротко перечисли, что уже готово; затем вноси нужные изменения в сам проект.

Игра:
- На стартовом экране покажи галерею игровых персонажей и дай выбрать одного. Используй изображения из images/characters/ и данные участников из mock-character-data.json, если эти файлы есть.
- Персонаж автоматически бежит вправо. Игрок перепрыгивает выбранные командой предметы на земле и приседает под выбранными командой низкими препятствиями.
- Собираемые командные бонусы пополняют энергию. Отдельный командный бонус временно увеличивает персонажа, затем размер возвращается к обычному.
- Участники описывают повседневные вещи, которые их утомляют, радуют и очень радуют, без упоминания игровой механики. Преобразуй эти ответы в добрые и легко узнаваемые игровые образы: усталость — в простые препятствия, обычную радость — в бонус энергии, большую радость — в редкий бонус временного роста. Не меняй смысл ответов, не используй конкретных людей и личные истории. Для препятствий сам выбери подходящий тип: на земле — перепрыгнуть, сверху — пригнуться.
- Если приложена уже готовая сводка `mock_vote_summary`, используй её категории `jump_over`, `duck_under`, `energy_pickup`, `temporary_growth_pickup` как источник идей и сохрани эти имена полей для игры. Покажи выбранные командой идеи на странице.
- Показывай счёт, запас энергии, понятный старт и повторный запуск, а также короткие инструкции управления.
- Управление: пробел/стрелка вверх — прыгнуть; стрелка вниз — присесть. На телефоне добавь крупные сенсорные кнопки.
- Если поле или файл данных отсутствует, страница должна показать понятное сообщение и всё равно дать запустить игру с разумными тестовыми данными.

Технические условия:
- Это статическая страница для GitHub Pages: index.html в корне, обычные HTML/CSS/JavaScript, без сервера, базы данных, ключей, сборщика и платных сервисов.
- Используй относительные пути вида ./images/... и ./mock-character-data.json, чтобы проект работал по адресу GitHub Pages с подпапкой репозитория.
- Не рассчитывай на запуск двойным щелчком по index.html: fetch локальных JSON-файлов требует HTTP. Сделай интерфейс понятным и для локального HTTP-сервера.
- Сделай адаптивную страницу, крупные читаемые кнопки, дружелюбную цветную графику и хорошую контрастность. Не загружай личные данные участников и не отправляй ответы на внешние сервисы.
- Не удаляй пользовательские файлы. Перед завершением сообщи, какие файлы изменены и как открыть игру локально.
- Не публикуй и не отправляй изменения в GitHub без отдельной команды ведущего.

Вот ответы на вопросы «что утомляет / что радует / что радует оооочень сильно»: [вставить обезличенную сводку]
Если категории `jump_over`, `duck_under`, `energy_pickup`, `temporary_growth_pickup` ещё не подготовлены, предложи добрые визуальные образы и покажи, как разложил идеи по этим категориям.
Вот файлы аватаров: [вставить список]
```

## 5. Промпт для публикации на GitHub Pages

Используйте, когда игра готова к публикации. Публикуйте только вымышленные тестовые данные и изображения, предназначенные для открытого сайта.

```text
Помоги опубликовать готовую статическую игру из этой папки в репозитории GitHub crazywoolf/game-challenge-test через GitHub Pages.

Сначала проверь git status, текущую ветку, remote и список файлов. Убедись, что index.html находится в корне и все JSON/изображения используют относительные пути. Не удаляй и не перезаписывай чужие изменения. Не публикуй реальные имена, фотографии, контакты или другие личные данные участников.

Нужный адрес сайта: https://crazywoolf.github.io/game-challenge-test/
Источник публикации Pages: ветка main, папка /(root), режим Deploy from a branch.

Подготовь изменения, проверь локально синтаксис и наличие всех файлов. Покажи краткий список изменений и точные команды. Если у тебя нет прямого доступа к GitHub, не пытайся читать приватный ключ или просить меня вставить пароль/token. Я отправлю изменения из своего Терминала через уже настроенный SSH remote:
  git push origin main

Если GitHub сообщает о запрете push, помоги посмотреть активные правила репозитория для main; не обходи их и не делай force push. После отправки подскажи, где проверить GitHub Actions/Pages и как открыть опубликованный адрес. Не говори, что сайт доступен, пока его открытие действительно не проверено.
```
